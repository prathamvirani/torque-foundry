# Torque Foundry Vibe-Coding Rules

1. No magic performance multipliers where a reasonable physical model can replace them.
2. Physics uses SI internally; display units are presentation.
3. Visuals are never authoritative simulation state.
4. Every major model gets at least one validation/reference case.
5. Approximations state assumptions and fidelity.
6. Beginner mode adds assistance, not fake physics.
7. Bad engineering ideas should usually be allowed and fail/explain naturally.
8. Prefer data definitions over hard-coded content branching.
9. Save-schema changes are versioned.
10. Research-grade systems remain separate until explicitly requested.
